# Кейс 2 «Smart Caspian Transit» — разбор

Источник: файл `cases/hackathon-cases-2026.docx` (оригинал в репозитории),
раздел «Кейсовые задания — два кейса для команд-участниц финала».
Полный текст обоих кейсов — в [`docs/cases.md`](docs/cases.md).

## Что от нас хотят

**Трек 3 · Цифровая экосистема МТК «Север–Юг».**
МТК «Север–Юг» — артерия Россия–Иран–Индия–Центральная Азия.
Каспийское море — критический узел: порты Астрахани, Махачкалы,
Энзели, Амирабада.

**Главная боль (дословно из кейса):** рассинхронизация между ж/д,
авто и морским транспортом, простои на таможне и непредсказуемость
погоды на море → срыв графиков.

**Задача:** концепция и прототип цифровой экосистемы (платформы),
которая обеспечивает бесшовное отслеживание груза и предсказывает
узкие места в каспийском звене МТК **до их возникновения**.

## Требования к результату (MVP) — все три закрыты прототипом

| № | Требование кейса | Где в прототипе |
|---|---|---|
| 1 | **Предиктивная модель:** прогноз задержек мультимодальных перевозок по историческим данным, погоде на Каспии и загруженности портов (стыковка ж/д и парома) | `backend/app/model.py` — объяснимый скоринг: волна/ветер (live Open-Meteo + реальный 90-дневный архив), загруженность порта, очередь на таможне, ожидание и пропуск парома (+48 ч). Monte Carlo P50/P90/P95 — квантили симуляции. Честно: открытой истории реальных задержек нет, ML-метки синтетические (`docs/ML_METHODOLOGY.md`). `GET /api/routes/{id}/forecast`, `GET /api/compare` |
| 2 | **Смарт-контракт / Цифровой коридор:** прототип автоматического таможенного оформления (pre-clearance) на распределённом реестре или защищённых API | Защищённые API + реестр документов в SQLite: статусы назначает **сервер** (симуляция таможенного органа, правила `demo-rules-v1`), клиент подаёт ссылки. Решение — в append-only hash-chain реестре (ledger v2: hash покрывает decision + снимок документов + issuer + версию правил). Это tamper-evident демо-механика, **не DLT/блокчейн**. `POST /api/clearance/submit`, `GET /api/clearance/ledger`, `GET /api/clearance/documents/{id}` |
| 3 | **Единое окно логиста:** цифровой двойник груза с расчётом углеродного следа (ESG) и альтернативными маршрутами при форс-мажоре | Главная страница: карта коридора (выбранный маршрут поиска подсвечен), двойник груза (таймлайн план/прогноз + фактические события), CO₂e на маршрут (DESNZ 2026, UK proxy — оценка), таблица 3 маршрутов, динамический поиск по графу (11 узлов, 17 рёбер), кнопка «Шторм на Каспии» и сценарии волна/ветер пересчитывают всё |

**Стек из кейса:** Predictive Analytics · Graph Databases · API-интеграции ·
Blockchain / Smart Contracts (опционально) · Digital Twin.
Наш стек: Python + FastAPI + SQLite (WAL), объяснимый скоринг вместо
«чёрного ящика», tamper-evident hash-chain реестр вместо полноценного
блокчейна (честно подписано), граф маршрутов — как структура данных
(узлы/рёбра) с API и динамическим поиском (Dijkstra + Yen).

## Честные ограничения (говорим на защите первыми)

- **В файле кейсов нет критериев оценки, сроков и формата защиты.**
  Их надо уточнить у организаторов — в `docs/PLAN.md` это первый пункт.
- **ML — эксперимент, обучается с нуля при старте** (`backend/app/ml.py`):
  ансамбль RandomForest + HistGradientBoosting, волна/ветер — bootstrap
  из реального 90-дневного архива Open-Meteo, но метки задержек —
  синтетические (правила коридора + шум): публичного датасета реальных
  задержек нет. Метрики (RF MAE 1,97 ч, R² 0,894) — **synthetic
  benchmark**, не точность на реальных рейсах. Реальные данные
  подключаются через CSV-контракт (`SCT_ML_HISTORY_CSV`,
  `docs/ML_DATA_CONTRACT.md`) и сбор событий.
- Реестр pre-clearance — **персистентный** (SQLite WAL, `store.py`),
  переживает рестарт; hash-chain — tamper-evident демо-механика, а не
  production-блокчейн/DLT. Статусы документов назначает сервер
  (симуляция таможенного органа), клиент не может присвоить «проверен».
- Загруженность портов и очереди на таможне — **демо-снимок**,
  живого открытого фида для них нет. Замена — один файл
  `backend/app/data.py`. События seed-грузов — demo-simulation,
  не GPS/AIS-трекинг.
- CO₂ — оценка по проверенным факторам DESNZ 2026 (UK proxy, indicative
  для РФ/Иран/КЗ), методология согласована с ISO 14083 / GLEC v3.3,
  **без верификации**; хабы/перегрузки/холостые пробеги не учтены.
  Ставки $/т-км — оценка (порядок величины Argus, окт 2025).
- Условные плечи: Махачкала–Амирабад/Энзели (линии не подтверждены),
  Актау–Бендер-Аббас (KTI, абстрактно) — маркированы `conditional=true`.

Первый прототип («Двойник Каспия», коммит `35b85d0d`) был про уровень
моря и экологию — это тема кейса №1, а не №2. По приказу Курбана он
полностью удалён из репозитория (коммит ниже заменяет дерево целиком),
сохранены только приёмы каркаса: FastAPI + статический фронт + Docker +
тесты + `run.sh`.
