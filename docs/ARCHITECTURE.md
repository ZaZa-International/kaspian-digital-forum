# Архитектура — Smart Caspian Transit (v0.3)

## Обзор

Монолит FastAPI + статический фронт, один процесс, без БД.
Состояние: демо-данные в `data.py`, реестр pre-clearance — в JSON-файле,
погода — внешний API с кэшем. Решение осознанное: для хакатона и пилота
на одном маршруте этого достаточно; горизонтальное масштабирование —
замена адаптеров данных, а не переписывание.

```
browser ──► FastAPI (app.main)
              ├── data.py        узлы, граф, маршруты, грузы, факторы
              ├── graph.py       Dijkstra + Yen k-shortest + Парето
              ├── model.py       скоринг, Monte Carlo, сценарии,
              │                  таймлайн, исключения, реестр (файл)
              ├── ml.py          ансамбль RF + HistGradientBoosting
              ├── weather.py     Open-Meteo live + архив 90 дней
              └── static/        HTML/CSS/JS + Leaflet (CDN)
```

## Ключевые решения и обоснования

1. **Граф вместо трёх маршрутов.** Коридор — направленный граф
   (11 узлов, 17 рёбер). Поиск — Dijkstra по прогнозному времени +
   Yen k=3 + Парето по времени/стоимости/CO₂. NetworkX не вводили:
   граф маленький, чистый stdlib быстрее и без зависимостей.
2. **Гибридный прогноз.** Скоринг — объяснимый бейзлайн и фолбэк;
   ML-ансамбль — вторая оценка. Если расходятся сильно — это сигнал,
   а не ошибка: показывается расхождение.
3. **Вероятностный ETA.** Monte Carlo (200 прогонов): волна/ветер —
   bootstrap из реального архива, загруженность/таможня — нормальное
   распределение вокруг значения. P50/P90/P95 + P(задержка > 24 ч).
4. **Сценарии как параметры.** Закрытие узлов, загруженность,
   таможня, волна/ветер — параметры прогноза, а не отдельные
   эндпоинты: один код считает и базовый, и сценарный прогноз.
5. **Реестр — файл, не БД.** Hash-chain в JSON: механика DLT
   показана честно, переживает рестарт, не требует инфраструктуры.
6. **Честность данных.** Каждый источник помечен: live / archive /
   default / demo. См. DATA_SOURCES.md.

## API (v0.3)

- `GET /api/health`, `/api/nodes`, `/api/ports`, `/api/weather`,
  `/api/weather/live`, `/api/corridor`
- `GET /api/graph` — узлы и рёбра
- `GET /api/routes`, `/api/routes/{id}/forecast` (параметры сценария:
  `close`, `extra_customs_h`, `wave_m`, `wind_ms`),
  `/api/routes/search?from_node&to_node&objective&k&close`
- `GET /api/compare` (+ P50/P90 в строках)
- `GET /api/shipments`, `/api/shipments/{id}`,
  `/api/shipments/{id}/timeline`
- `GET /api/exceptions`
- `POST /api/clearance/submit`, `GET /api/clearance/ledger`
- `GET /api/ml/info`, `/api/ml/forecast`, `/api/ml/shipment/{id}`

## Ограничения (известные, честные)

- Нет аутентификации и rate limiting — прототип для демо; для
  пилота нужен API-ключ и RBAC.
- Загруженность портов и очереди таможни — демо-снимок.
- ML-метки — по правилам коридора; реальная точность появится
  только с историей план/факт (см. ML_METHODOLOGY.md).
- Фронт зависит от CDN Leaflet/OSM; без интернета карта не
  грузится (таблицы и двойник работают). Локальные копии — в Iter 2.
- Реестр — один файл, без конкурентной записи и репликации.
