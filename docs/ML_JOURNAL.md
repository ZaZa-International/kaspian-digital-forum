# Журнал прогнозов и фактических исходов

Журнал фиксирует прогноз до результата и позволяет проверить его по
сообщённому оператором прибытию. Он не обучает модель автоматически.

## Использование

На вкладке «ML-прогноз» откройте «Журнал проверки на рейсах» и нажмите
«Сохранить прогноз». Для сохранения выключите шторм и сбросьте сценарий.
Снимок содержит время расчёта, текущую версию плана, оставшиеся плечи,
базовое время, признаки, прогноз, интервал и хеши модели и датасета.
Повтор запроса с тем же `Idempotency-Key` не создаёт второй снимок.

После зарегистрированного прибытия на последнем плече журнал проверяет
фактическое время, время получения записи и завершённость движения.
При исправлении события используется актуальная запись. Целевая задержка:

`max(0, фактическое время от снимка до прибытия − базовое оставшееся время)`.

Демонстрационные грузы и снимки прежней версии маршрута исключаются.
Записи без явного времени факта, с ещё неизвестным результатом или
незавершённым движением ожидают уточнения. Противоречивые прибытия не
становятся учебными метками. Признаки после исхода не пересчитываются.

## Что означают метрики

Журнал сравнивает ML и оперативный расчёт с одинаковыми исходами:
средняя абсолютная ошибка задержки и эмпирическое покрытие сохранённых
интервалов. Покрытие измеряется и для экспериментальных интервалов,
даже если они не допущены к использованию в рабочем ETA.

Единица метрики — **снимок**. Несколько снимков одной перевозки связаны
между собой и не являются независимыми рейсами. Сведения оператора не
подтверждают достоверность внешним источником. До появления подходящей
истории качество на реальных перевозках неизвестно.

## API и экспорт

- `POST /api/operations/{id}/intelligence/snapshots` — сохранить текущий
  прогноз. Работает обычная защита записи `X-Write-Token`, когда задан
  `SCT_WRITE_TOKEN`. Параметры «что если» и непустое тело отклоняются.
- `GET /api/operations/{id}/intelligence/snapshots?limit=50` — список
  снимков, статусы и метрики. Чтение не создаёт снимков.
- `GET /api/operations/{id}/intelligence/snapshots.csv` — история груза.
- `GET /api/operations/intelligence/snapshots.csv` — история всех грузов.

CSV содержит только первый пригодный снимок каждой перевозки, чтобы
один груз не повторялся в разных частях обучения. Сохраняются время
прогноза `forecast_at`, факт `outcome_at`, доступность результата
`observed_at`, признаки, метка, идентификаторы и происхождение события.
Текст источника снабжён префиксом `operator-reported:`. Заголовок
`Cache-Control: no-store` запрещает кеширование выгрузки браузером.

CSV готовится согласно [контракту](ML_DATA_CONTRACT.md). Для обучения
нужен минимальный объём истории и достаточно данных после временного
разделения. Один успешно сверенный снимок не заменяет такую проверку.
Сброс демо очищает журнал вместе с остальными данными демонстрации.
