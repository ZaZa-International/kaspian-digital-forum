# План команды на 2 дня хакатона — кейс 2 «Smart Caspian Transit»

Хакатон — два дня (13–14 ноября 2026). Роли условные: на 3–4 человек
каждый берёт блок, Курбан — капитан и питч.

## День 1 — 13 ноября: продукт готов к защите

### 08:00–09:00 — Сверка с организаторами (самое важное)

- [ ] Уточнить **критерии оценки, регламент и формат защиты** —
      в файле кейсов их нет (ни баллов, ни времени питча, ни дедлайна сдачи).
- [ ] Уточнить, есть ли исторические данные / API погоды / портов.
- [ ] Подтвердить состав команды и кто защищает.

### 09:00–11:00 — Данные и модель

- [ ] Проверить живую погоду: открыть `/api/weather/live` — должен
      быть `live: Open-Meteo`. Если на площадке нет интернета —
      демо-фолбэк работает сам, ничего не чинить.
- [ ] Если дали реальные данные (история рейсов, загруженность) —
      заменить демо-снимок в `backend/app/data.py` и переобучить ML
      (`python3 scripts/fetch_weather_archive.py` — для погоды).
- [ ] Прогнать `pytest -q`, проверить `/docs`.

### 11:00–14:00 — Фронт и демо

- [ ] Главный экран: карта + сравнение + калькулятор + двойник груза +
      pre-clearance + порты. Ничего лишнего не добавлять.
- [ ] Мобильная вёрстка: KPI по 2 в ряд, без горизонтального скролла.
- [ ] Скриншоты карты и таблицы — запасной вариант без интернета.
- [ ] Локальные копии Leaflet — если на площадке нет интернета.

### 14:00–17:00 — Защита (репетиция)

- [ ] Репетиция питча по `docs/PITCH.md` — 3 минуты, с таймером,
      минимум 3 прогона. Главные клики: кнопка шторма, калькулятор
      своего груза, pre-clearance по SHP-1043 и SHP-1044.
- [ ] Подготовить ответы на вопросы из `PITCH.md`.
- [ ] Проверить запуск с нуля на чистом ноутбуке: `git pull` →
      `./run.sh` → открыть страницу. Если дольше 2 минут — чинить.
- [ ] Залить финальный коммит дня, проверить свежую версию на GitHub.

## День 2 — 14 ноября: усиление и финал

### 09:00–12:00 — Обратная связь и доработки

- [ ] Собрать вопросы и замечания с первого дня / от менторов.
- [ ] Приоритет доработок: (1) живые данные портов, если дали доступ;
      (2) история рейсов в ML; (3) косметика фронта. Не начинать
      новых больших фич.
- [ ] Прогон демо-сценария целиком с таймером, дважды.

### 12:00–15:00 — Финальная защита

- [ ] Один человек говорит, второй — за клавиатурой (шторм,
      калькулятор, pre-clearance), третий — страхует запасными
      скриншотами.
- [ ] После защиты: записать вопросы жюри — они пригодятся для
      пилота (см. `docs/ROADMAP.md`).
- [ ] Если будет предложение о пилоте — зафиксировать контакт
      и следующий шаг прямо на месте.

## Если что-то пошло не так

| Проблема | Действие |
|---|---|
| Дали реальные данные поздно | Меняем только `data.py`, фронт и API не трогаем |
| Нет интернета на площадке | Локальный запуск + скриншоты; Leaflet локально; погода — демо-фолбэк |
| Падает бэкенд | `docker compose up` как план Б; фронт показывает ошибку честно |
| Не хватает времени | Режем реестр до одной кнопки, оставляем карту + прогноз + шторм |
