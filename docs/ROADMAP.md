# План улучшения продукта — Smart Caspian Transit

Дорожная карта после хакатона: от прототипа к пилоту, который можно
показать порту, таможне и республике. Упорядочено по ценности для
пользователя, а не по сложности.

## Фаза 1 — Пилот в Махачкале (2–4 недели после хакатона)

**Цель:** один реальный груз, один реальный маршрут, измеренный результат.

- [ ] **Живые данные порта Махачкала**: загруженность причалов и очередь
      судов — сначала ручной ввод диспетчером (форма в админке), затем
      интеграция с системой порта. Сейчас это демо-снимок — главный
      пробел прототипа.
- [ ] **Прогноз погоды — из Open-Meteo уже живой**; добавить прогноз
      на 7 дней вперёд и предупреждения за 48 часов до шторма.
- [ ] **История рейсов**: начать копить факт — план/факт по каждому
      грузу. Через 50–100 рейсов скоринг и ML переобучаются на
      реальных задержках (пайплайн уже готов).
- [ ] **Pre-clearance с реальным пакетом документов**: загрузка сканов,
      проверка комплектности по типу груза, интеграция с API таможни
      (пилот — одна таможенная процедура, один пост).
- [ ] **Метрика пилота**: доля грузов, пришедших в прогноз ±6 ч;
      среднее сокращение простоя на стыковке; экономия CO₂ на
      выбранных маршрутах. Без цифр пилот не продать.

## Фаза 2 — Коридор целиком (1–3 месяца)

- [ ] **Все узлы коридора**: Астрахань, Актау, Баку, Туркменбаши,
      Энзели, Амирабад, Астара — живые статусы, а не демо.
- [ ] **Расписания паромов как есть**: у каспийских паромов нет
      фиксированного расписания — показывать окно отправления с
      вероятностью, а не фиктивное время.
- [ ] **Графовая модель коридора**: маршруты как граф (сейчас — 3
      фиксированных маршрута), автоматический поиск альтернатив
      при закрытии узла (Дийкстра по времени/стоимости/CO₂).
- [ ] **Уведомления**: Telegram/Max-бот для логиста — «ваш груз
      задерживается на 12 ч, рекомендуем R3», «шторм через 36 ч».
- [ ] **Реестр pre-clearance — в production**: вынести hash-chain
      в отдельный сервис, подключить электронную подпись, журнал
      аудита для таможни.

## Фаза 3 — Платформа (3–6 месяцев)

- [ ] **Мобильное приложение логиста**: тот же бэкенд, нативный
      клиент (скан накладной, push о статусе груза).
- [ ] **ML на реальных данных**: градиентный бустинг на накопленной
      истории; прогноз не только задержки, но и её причины;
      объяснимость (SHAP) для каждого прогноза.
- [ ] **Биржа мощностей**: свободные места на паромах и вагонах —
      маркетплейс внутри платформы (монетизация).
- [ ] **ESG-отчётность**: автоматический отчёт по CO₂ на груз
      для грузоотправителей (ISO 14083), сравнение с автодорогой.
- [ ] **Мультиязычность**: русский, английский, фарси, азербайджанский,
      казахский — для всех стран коридора.

## Что нужно от партнёров (для переговоров)

| Партнёр | Что просим | Что даём |
|---|---|---|
| Порт Махачкала | Данные о загруженности, пилот на 1 маршруте | Прогноз стыковок, меньше простоев |
| Таможня (Дагестан) | Пилот pre-clearance на 1 посту | Меньше очередей, прозрачный реестр |
| РЖД / экспедиторы | История рейсов (обезличенная) | Точный прогноз, выбор маршрута |
| Минцифры Дагестана | Пилотный контракт, доступ к данным | Цифровой двойник хаба республики |

## Риски и как их закрываем

- **Нет живых данных портов** → начинаем с ручного ввода диспетчера,
  ценность появляется до интеграций.
- **Паромы без расписания** → честно моделируем окно отправления
  с вероятностью, а не выдумываем рейсы.
- **Доверие к прогнозу** → каждый прогноз объясним (причины по часам),
  метрика точности публикуется в самом продукте.
- **Масштаб** → stateless API + статический фронт; данные — из внешних
  источников, горизонтальное масштабирование без переделок.
