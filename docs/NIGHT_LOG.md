## Цикл 3 — 02:00–02:10 MSK — P0: персистентность прода через entrypoint

**Проблема:** прод-том `kdf_kdf-data` создан root'ом старого образа; контейнер
работает от appuser (uid 1000) → запись невозможна → fallback в /tmp (данные
не переживают пересоздание контейнера). Серверный том и деплой-конфиг вне
репозитория — трогать нельзя. Единственный рычаг внутри репозитория — образ.

**Сделано (стандартный паттерн postgres/mysql):**
- `backend/entrypoint.sh`: если старт от root — `chown` каталога данных
  (`SCT_DATA_DIR` или `/app/backend/app/data`) на appuser, затем `setpriv`
  сбрасывает привилегии до appuser и exec'ает сервер. Если старт уже non-root
  (деплой-compose может пинить `user:`) — просто exec; store.py честно
  деградирует в /tmp. Скрипт может только помочь, не ломает старт.
- `Dockerfile`: `USER root` + `ENTRYPOINT [entrypoint.sh]`; сам uvicorn
  работает от appuser (uid 1000). `setpriv` есть в python:3.12-slim (проверено),
  доп. пакетов не нужно.

**Проверки (локально, до пуша):**
- Сборка образа OK. Том принудительно сделан root-owned (`chown root:root`),
  контейнер запущен с ним: `/api/health` → `store.ok:true`, путь на томе,
  **fallback исчез**; том стал `1000:1000`; процесс uvicorn — **uid 1000**
  (не root). Создан SHP-2001 → `docker restart` → груз пережил рестарт.
- Запуск с `--user appuser` (имитация пина в деплой-compose): старт ok,
  без краша (защитная ветка entrypoint работает).
- Тестовые контейнеры/тома удалены, прод kdf-app не тронут.
