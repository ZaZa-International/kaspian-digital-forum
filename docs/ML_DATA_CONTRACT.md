# История для обучения модели задержек

Для обучения нужны неизменяемые снимки прогноза и фактическое время доставки. Один снимок на завершённую перевозку. Файл можно подготовить из журнала прогнозов и фактов приложения или сформировать из собственной истории по той же схеме. Данные встроенной симуляции хранятся отдельно от пользовательской истории.

## Что сохранять в момент прогноза

Сохраняйте значения по оставшимся плечам версии плана, действующей в момент прогноза. Для погоды и очередей используйте прогнозы или оценки, доступные в этот момент. Пересчёт признаков по будущим наблюдениям приводит к утечке данных. Для плеча в движении оставшаяся дистанция оценивается по доле оставшегося базового времени. Задержку на маршруте, изменённом после снимка, нельзя приписывать исходному плану.

| Колонка | Допустимые значения | Что записать |
|---|---|---|
| `max_wave_m` | 0–15 м | Максимальная прогнозная значимая высота волны на оставшихся морских плечах |
| `max_wind_ms` | 0–60 м/с | Максимальный прогнозный ветер на этих плечах |
| `max_congestion_pct` | 0–100% | Максимальная оценка загруженности портов на оставшемся маршруте |
| `total_customs_h` | 0–3000 ч | Сумма оценок оставшегося времени таможенных очередей |
| `sea_km` | 0–20 000 км | Оставшееся расстояние по морю |
| `rail_km` | 0–20 000 км | Оставшееся расстояние по железной дороге |
| `weight_t` | больше 0, до 5000 т включительно | Масса груза |
| `sea_legs` | целое от 0 до 20 | Число оставшихся морских плеч. Без морских плеч волна, ветер и морская дистанция равны 0 |
| `delay_h` | 0–8760 ч | `max(0, фактическое прибытие − базовое время прибытия из сохранённого снимка)` в часах. База включает ожидаемое штатное ожидание парома |
| `forecast_at` | ISO 8601 со смещением | Момент сохранения снимка. `departed_at` допустим как алиас, если снимок сделан при отправлении |
| `observed_at` | ISO 8601 со смещением | Момент, когда факт и метка стали доступны системе. Используйте время получения факта, если оно позже времени прибытия. Допустимый алиас `label_available_at` |
| `shipment_id` | Строка до 128 символов | Необязательный идентификатор. Если столбец присутствует, каждое значение обязательно и уникально |

Времена нормализуются в UTC. `observed_at` должен быть позже `forecast_at`. Числа должны быть конечными. CSV принимается в UTF-8, размером до 16 МиБ и до 50 000 строк. Для обучения нужно минимум 120 строк до исключений. После группировки одинаковых времён и исключения меток, которые стали известны слишком поздно, минимумы составляют 40 для обучения и по 15 для валидации, калибровки и теста. При длинном транзите понадобится больше строк или более широкий период наблюдений. Если `shipment_id` отсутствует, дедупликацию перевозок проверяет поставщик данных.

## Подключение и проверка

1. Проверьте полноту, происхождение и право на использование истории. Уберите повторные снимки одной перевозки, сценарные записи и неподтверждённые факты из обучающего набора.
2. Запустите оценку `python scripts/evaluate_ml.py --history /path/to/history.csv --walk-forward`. Проверьте окна времени, исключения, MAE и покрытие интервала. [CSV-шаблон](../scripts/ml_history_template.csv) иллюстрирует поля тремя вымышленными строками. Для обучения добавьте собственную историю нужного объёма.
3. Запустите сервер с `SCT_ML_HISTORY_CSV=/path/to/history.csv`. Модель загружается при первом запросе и переобучается при смене файла или его метаданных. Публикуйте обновление файла атомарной заменой.
4. Проверьте `GET /api/ml/info`. `dataset.source_kind` показывает `csv`, а `dataset.partitions` содержит размеры и временные границы. Ошибка ввода возвращает `status=unavailable`, прогноз остаётся на объяснимом скоринге. Без `SCT_ML_HISTORY_CSV` сервер использует демонстрационный набор.

Защита от утечки учитывает время получения исхода. История из ранней выборки участвует в последующем этапе, только если её метка была известна до первого снимка следующего окна. Хеш SHA‑256 считается по признакам, целям, нормализованным временам и схеме. Это идентификатор версии данных. Он не удостоверяет их происхождение.
