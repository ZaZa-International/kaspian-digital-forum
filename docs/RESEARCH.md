**Коротко (вывод):** для pre-clearance/единого окна применимы: (1) событийная модель DCSA T&T как каркас статусов и исключений; (2) DCSA Port Call как паттерн синхронизации ETA/ETB между портом, паромом и таможней; (3) eBL-паттерн структурированного документа со статусами; (4) MMT/BSP + UN/LOCODE как семантическая модель данных. DCSA — контейнерная отрасль; каспийские перевозки преимущественно RoRo/жд-паром/налив, требуется адаптация, а не «соответствие DCSA».

Есть первичные операционные снапшоты (Курык, ships.asco.az, Баку-пресс-релизы) без открытой лицензии и архива. Для прототипа: собственный сбор событий + синтетическая калибровка, явно помеченная как демо-данные.

### Предлагаемая schema собственного сбора событий

```text
ferry_event
  event_id        uuid
  vessel_name     text          -- как в источнике
  imo / mmsi      text nullable -- из ссылок MarineTraffic (Курык/ASCO)
  route_from      text          -- UN/LOCODE (напр. AZALY Alat, KZKUR Kuryk)
  route_to        text
  event_type      enum          -- departure | arrival | berth | anchorage | approach
  planned_ts      timestamptz   -- опубликованный ETA/план (если есть)
  actual_ts       timestamptz   -- фактическое время из снапшота
  eta_published_ts timestamptz  -- когда ETA был опубликован (версия снапшота)
  delay_hours     numeric       -- actual − planned (производное)
  cause           enum nullable -- weather | congestion | loading | customs | unknown
  cargo_units     jsonb         -- {"trucks": 45, "railcars": 30, "tonnes": ...}
  source_url      text
  snapshot_ts     timestamptz   -- время парсинга (снапшоты hourly)
  raw_html_ref    text          -- ссылка на сохранённый сырой снапшот
  license_note    text          -- "no open license; internal research use"

port_call
  port_code, vessel_imo, berth_no,
  eta / etb / etd (planned vs actual), operation_type, waiting_reason,
  source_url, snapshot_ts

weather_hourly (Open-Meteo, CC BY 4.0)
  lat, lon, ts, wave_height_m, wave_period_s, wind_speed, source_model
  -- join к ferry_event по маршруту/времени для признака «метео»
```

Сбор: hourly-снапшоты `ships.asco.az` + `portkuryk.kz/ru/dispoziciya-sudov` (+ расписание), дедупликация по (vessel, event_type, ts), delay = факт − последний опубликованный ETA. Хранить сырые снапшоты для воспроизводимости.

## Блокеры и что нельзя заявлять

### Блокеры (проверить позже)
1. **Значения 32.74 / 63.28 / 97.49 g CO2e/t-km не подтверждены**: отсутствуют во всех проверенных изданиях DESNZ 2023–2026. Происхождение неизвестно — не использовать как DESNZ-факторы.
2. **unece.org — 403 (Cloudflare)**: рекомендации UN/CEFACT по единому окну/электронным документам (номера, содержание) не верифицированы. Проверены только MMT/BSP артефакты на официальном GitHub и vocabulary.uncefact.org.
3. **iso.org**: прямая страница ISO 14083:2023 не открыта (использован EVS — официальный нац. орган). Полный текст стандарта платный; требования к заявлению о соответствии изучены по GLEC, не по тексту ISO.
4. **РФ-источники недоступны**: morflot.ru (403), asop.ru (нет соединения), сайты портов Астрахань/Махачкала (домены не подтверждены). Иранские порты (amirabadport.ir, anzaliport.ir) — недоступны, домены не подтверждены.
5. **asco.az — 403** (основной сайт); работает только ships.asco.az. Цитата о телефонах маршрутов зафиксирована через поисковый сниппет — перепроверить.
6. **Нет открытого исторического датасета** по задержкам паромов/загрузке каспийских портов. Курык и ships.asco.az — снапшоты без лицензии и архива; AISHub требует свой приёмник и запрещает редистрибуцию raw; MarineTraffic/Kpler — платно. Покрытие Каспия AISHub не проверено (JS-карта).
7. **Махачкала–Амирабад/Энзели**: действующая регулярная паромная линия и времена переходов не подтверждены (только тесты/планы 2020 и анонсы 2026).
8. **Open-Meteo free tier — non-commercial**: для коммерческого использования нужна подписка; атрибуция обязательна в любом случае.
9. **PortXchange**: portxchange.com припаркован (продаётся); использовать port-xchange.com.
10. **GLEC v3.3 PDF**: таблицы default intensities извлечены с искажениями — конкретные числа Ferry-RoPax перед кодом сверить с оригиналом PDF.
11. **CountEmissionsEU (EU) 2026/1030**: номер/даты известны только из текста GLEC v3.3 — сверить с EUR-Lex.

### Что нельзя заявлять
- «ISO 14083 compliant» / «GLEC certified» — только «aligned with ISO 14083 / GLEC v3.3 methodology», без верификации assurance-провайдером.
- Факторы DESNZ как валидированные для РФ/Ирана/Казахстана — это UK proxy (UK парк, UK rail >98% дизель, UK energy mix; морские — международные средние IMO 2009). Только indicative-оценка с оговоркой.
- Числа 32.74 / 63.28 / 97.49 как «официальные DESNZ» — не подтверждены.
- Маркетинговые цифры вендоров (Portchain «800k t CO2», project44 «72% faster», FourKites кейсы) как независимые факты; и тем более приписывать им победы на хакатонах.
- Существование открытых исторических данных по задержкам Каспия — их нет; демо-данные прототипа должны быть явно помечены как синтетические/собранные снапшоты.
- Фиксированное расписание паромов и гарантированные времена переходов — только диапазоны и ETA с неопределённостью (погода, загрузка, таможня).
- Бесплатность Open-Meteo для коммерческого продукта.
- Соответствие DCSA-стандартам для каспийского RoRo/жд-паромного сегмента — только «паттерны, адаптированные из DCSA».
