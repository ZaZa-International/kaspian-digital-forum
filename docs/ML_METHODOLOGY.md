# ML-методология — Smart Caspian Transit

**Статус: эксперимент.** Модель обучается **с нуля при старте**
приложения (не «дообучается» на проде). Метки задержек синтетические,
метрики — **synthetic benchmark**: качество воспроизведения генератора,
НЕ точность прогноза реальных рейсов. Это подписано в `/api/ml/info`
и на экране.

## Задача

Предсказать задержку груза (часы) по признакам маршрута и погоды.
Вторая оценка рядом с объяснимым скорингом: если две независимые
оценки сошлись — прогнозу можно верить; расхождение показывается явно.

## Модели

Ансамбль: **RandomForest (200 деревьев) + HistGradientBoosting**,
прогноз — среднее двух. Baseline — LinearRegression.
Обучение при старте, <2 с, 800 примеров, сплит 80/20
(фиксированный seed 42).

## Признаки (8)

`max_wave_m`, `max_wind_ms`, `max_congestion_pct`, `total_customs_h`,
`sea_km`, `rail_km`, `weight_t`, `sea_legs`.

## Данные — честно

- **Волна/ветер — реальные распределения**: bootstrap из 90-дневного
  архива Open-Meteo (`archive_weather.json`) для двух морских плеч.
  Сэмплы прорежены (каждый 6-й час, 364 точки/сегмент); статистики
  метаданных — по полному архиву.
- **Загруженность/таможня — равномерно** (20–95%, 0–20 ч):
  открытого фида нет.
- **Метки — по правилам коридора + шум N(0; 2,5)**: публичного
  датасета реальных задержек не существует (RESEARCH.md §6).
  Это главный предел модели.

## Метрики (holdout, 160 примеров; перепроверено 12.11.2026)

| Модель | MAE, ч | R² |
|---|---|---|
| RandomForest | 1,97 | 0,894 |
| HistGradientBoosting | 2,32 | 0,826 |
| **Ансамбль RF+HGB** | **2,07** | **0,877** |
| LinearRegression | 2,45 | 0,818 |

**Важно:** ансамбль НЕ лучше RandomForest на этих данных — он
выбран за устойчивость к выбросам, а не за метрику. Мы публикуем
все четыре строки, а не только лучшую. Повторяем: это **synthetic
benchmark**, не точность прогноза реальных перевозок. Так и говорить
на защите.

Важность факторов (RF): таможня 0,49, загруженность 0,29,
волна 0,17.

## Реальные данные: CSV-контракт

- `SCT_ML_HISTORY_CSV=/path/to/history.csv` — обучение на реальных
  завершённых перевозках вместо генератора. Контракт колонок, требования
  и шаблон — `docs/ML_DATA_CONTRACT.md`, `scripts/ml_history_template.csv`.
- При наличии `departed_at` — **хронологический split 80/20** (по времени,
  не случайный); без него — random 80/20 с пометкой в метаданных.
- Невалидный CSV (пропуски, отрицательные задержки, не-числа) → ошибка,
  молчаливого обучения на битых данных нет.
- Воспроизводимость: в `/api/ml/info` — kind датасета, **hash (SHA-256
  от X,y), seed, split, версии scikit-learn/numpy**, метрики всех моделей.
  Повторное обучение на тех же данных даёт идентичные метрики (тест).
- Альтернативный путь накопления факта: `POST /api/shipments/{id}/events`
  (фактические события, `source` обязателен, `received_ts` сервера).

## Сценарии

ML учитывает сценарии так же, как скоринг: `route_features` использует
тот же приоритет (явная волна/ветер > шторм > live/fallback), доп.
таможню на каждом плече и закрытые узлы (422/ошибка). Эндпоинты
`/api/ml/forecast` и `/api/ml/shipment/{id}` принимают `close`,
`extra_customs_h`, `wave_m`, `wind_ms`.

## Объяснимость

Глобальная — важность факторов. Локальная — **окклюзионная
атрибуция**: каждый признак по очереди заменяется медианой
обучающей выборки, изменение прогноза — вклад признака
(в часах). Это не SHAP (SHAP не вводили ради одной зависимости),
метод назван своим именем в коде и в API.

## Что дальше

1. Собирать историю план/факт (CSV-контракт + события, см. ROADMAP):
   тогда метки станут реальными; для production — walk-forward.
2. Калибровка вероятностей (Platt/isotonic) вместо эвристики
   delay/(delay+18) — когда появятся реальные метки.
3. Монотонные ограничения: больше волна → не меньше задержка.
4. Опционально: LightGBM/CatBoost в сравнение моделей (та же рамка).
