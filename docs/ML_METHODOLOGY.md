# ML-прогноз задержки Smart Caspian Transit

ML оценивает дополнительные часы сверх базового времени оставшегося пути. База включает штатное ожидание парома. Пульт использует объяснимый скоринг для расчёта ETA, сравнения планов и решений оператора. Оценку ML и интервал можно посмотреть рядом.

## Данные и разделение

Встроенный набор состоит из 800 сценариев. Выбор маршрутов и оставшихся участков основан на графе коридора, включая продолжения через Баку и Энзели. Для волны и ветра используются независимые выборки из архивных распределений Open‑Meteo. Источник не содержит общего индекса времени для двух рядов. Загруженность, очереди, фаза движения и задержки моделируются. В целевой переменной есть шум, редкие дополнительные задержки и правила коридора. Сравнение с объяснимым скорингом поэтому не является независимой проверкой точности на реальных рейсах.

Демонстрационный набор делится на 440 / 120 / 120 / 120 снимков по фиксированному генератору с seed 42. Для пользовательского CSV окна идут по времени снимка в UTC. Снимки одного момента не пересекают границу окон. Метка попадает в раннее окно, только если она была доступна до начала следующего. [Контракт истории](ML_DATA_CONTRACT.md)

| Выборка | Назначение |
|---|---|
| Train | Обучение RandomForest, HistGradientBoosting и двух базовых оценок (линейная регрессия и медиана). Медианы признаков и масштабы L1 считаются здесь же |
| Validation | Выбор доли RandomForest в смеси из 25%, 50% и 75%. Затем выбор модели с наименьшим MAE, включая базовые оценки. При точном равенстве выбирается более простая оценка |
| Calibration | Расчёт радиуса предиктивного интервала по абсолютным ошибкам выбранной модели |
| Test | Оценка после фиксации модели и интервала. Публикуются MAE, RMSE, R², число примеров и фактическое покрытие |

В интерфейсе глобальная важность признаков рассчитывается по RandomForest. Локальные вклады относятся к выбранной модели. Каждый признак по очереди заменяется медианой train и измеряется изменение ответа. Базовый прогноз и восемь замен вычисляются одним пакетом на модель. Вклады могут пересекаться и не складываются в прогноз. Похожие примеры берутся только из train. Их источник подписан.

## Метрики встроенной симуляции

Один воспроизводимый прогон на тестовой выборке из 120 синтетических снимков. В валидации выбран RandomForest с MAE 4,177 ч. В таблице все модели оценены на одной тестовой выборке.

| Модель | MAE, ч | RMSE, ч | R² |
|---|---:|---:|---:|
| RandomForest | 3,683 | 4,833 | 0,9025 |
| Смесь RF + HGB с весом из валидации | 3,741 | 4,834 | 0,9024 |
| Смесь RF + HGB с равными весами | 3,824 | 4,920 | 0,8989 |
| HistGradientBoosting | 4,039 | 5,329 | 0,8814 |
| Линейная регрессия | 5,597 | 8,044 | 0,7298 |
| Медиана train | 11,484 | 15,559 | −0,0107 |

Номинальный уровень интервала 90%. На тесте в интервал попали 110 из 120 целей (91,67%). Средняя ширина 15,085 ч. Радиус 7,897 ч. Это показатели на встроенной симуляции. Для реальных рейсов покрытие и ошибка ещё не измерены.

## Интервал и применимость

Split conformal берёт абсолютную ошибку с порядковым номером `ceil((n_calibration + 1) × 0,90)` в отсортированном наборе ошибок калибровки. Нижняя граница ограничена нулём. Гарантия относится к среднему покрытию новых примеров при сопоставимых, обменяемых данных. Она не задаёт вероятность для отдельной перевозки. Временной дрейф погоды, работы портов или структуры грузов может ухудшить покрытие.

API показывает диапазоны каждого признака из train и порог расстояния от медианы (95-й перцентиль L1 с масштабированием по медианному абсолютному отклонению). Выход за любую границу или порог даёт `out_of_distribution`. Флаг `interval.calibration_applicable` означает, что проверка известных границ прошла. Поля для дорожной дистанции, фазы движения и сообщённой оператором задержки в текущей схеме отсутствуют. При их влиянии на перевозку API помечает ограничения. `interval.usable` отражает допуск к использованию в ETA. Сейчас он выключен для синтетических данных и CSV с неподтверждённым происхождением. В обоих режимах предпочитается объяснимый скоринг.

## Повторение оценки

```sh
python scripts/evaluate_ml.py --samples 50
python scripts/evaluate_ml.py --history /path/to/history.csv --walk-forward
```

CLI печатает те же метрики и замеры времени прогноза с готовыми признаками. Время HTTP, базы и запросов погоды в эти замеры не входит. Режим walk-forward выполняет до двух дополнительных оценок на более ранних расширяющихся окнах. Для каждого окна модели переобучаются и выбираются заново. При недостаточном объёме выводится `insufficient_data`. Диагностические окна могут пересекаться и не используются для выбора модели основного теста.

`GET /api/ml/info` публикует хеш данных, версию и хеш конфигурации модели, размеры окон и версии библиотек. Хеш модели идентифицирует воспроизводимый прогон, включая настройки, источник и калибровку. В прогнозах дополнительно указываются источник истории, выбранная модель и причины перехода к скорингу. [Open‑Meteo Marine API](https://open-meteo.com/en/docs/marine-weather-api)
