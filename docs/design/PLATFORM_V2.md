# Платформа V2 · направление и критерии

Статус: инструкция для реализации, 13 ноября 2026. Это направление, а не отчёт о готовности интерфейса. Исходные скриншоты просмотрены; новая реализация в рамках этой работы не проверялась.

## Главная задача

Диспетчер открывает платформу, узнаёт, какой груз требует решения, видит его положение на маршруте и совершает следующее действие. Карта — рабочий инструмент первого экрана. Пользователь уже выбрал светлый Freight на главной; переносим его белый фон, тёмную типографику, кобальтовый акцент и простые контуры в рабочую часть. Главную `/`, ролик грузовика и знак «Коридор C» сохраняем.

Предпосылки: основной пользователь — диспетчер; данные, API и текущие URL сохраняются; карта показывает расчётную схему коридора, а не спутниковый трек. Эти предпосылки выведены из текущего продукта. Отдельного пользовательского утверждения новых деталей композиции пока нет.

**Визуальный тезис:** светлая рабочая среда Freight с белыми плоскостями, угольным текстом, кобальтовым выбором, существующим IBM Plex Sans для данных и Oswald только для коротких заголовков, сеткой 4 px, плоскими панелями и радиусом 4–8 px; фактическая география становится главным изображением.

**Интерактивный тезис:** выбор отвечает сразу, hover меняет фон за 120 ms, панели входят/уходят за 180–220 ms через opacity/transform; карта перемещается только от действий пользователя, прокрутка страниц обычная, без bounce, авторотации и появления данных с задержкой.

Allowed patterns: моноширинные идентификаторы и версии планов; тонкие разделители строк; географические подписи; короткое движение камеры после «Вписать маршрут». Градиенты, стеклянные панели и декоративные диаграммы не нужны.

## Design DNA

Цвета Freight прочитаны из `backend/app/static/freight-hero.css`, не оценены по изображению. Дополнительные нейтрали ниже — предложенные токены.

| Роль | Значение | Применение |
| --- | --- | --- |
| Background / surface | `#ffffff` | Основная среда, панели |
| Ground | `#f4f6f8` | Отделение карты и рабочей поверхности |
| Ink | `#151515` | Заголовки и основной текст |
| Muted | `#505050` | Подписи и вторичные сведения |
| Accent | `#254fe1` | Главная кнопка, выбранный груз, принятый путь |
| Selection tint | `#edf1ff` | Выбранная строка; узкая синяя боковая линия |
| Divider | `#e2e2e2` | Разделитель, не единственный контур интерактивного поля |
| Control boundary | `#767676` | Достаточно заметные границы полей/контролов |
| Danger | `#b42318` | Просрочено / критично + обязательная подпись |
| Warning | `#925700` | Требует внимания + обязательная подпись |
| Success | `#17613e` | Завершено / проверено + обязательная подпись |

Типографика: IBM Plex Sans 14–16/20–24 для рабочего текста; 12/16 только для вспомогательных ID и источников; заголовки страниц 28–32 desktop, 23–26 mobile; заголовки панелей 17–20. Моноширинный шрифт — для ID, не всех микроподписей. Oswald допустим в одном коротком заголовке, но не в таблице или длинной кириллице.

Отступы 4/8/12/16/24/32. Разделители важнее теней. Тень только у плавающего drawer/popover. Размер hit area 44×44, видимый icon может быть 16–20 px. Фокус — 2 px cobalt с отступом 3 px. Состояния кнопок: обычное, hover, focus, pressed/selected, disabled; selected не маскировать под disabled.

Сохранить форму утверждённого C, не рисовать новый знак. В рабочей шапке знак 24–28 px и компактный wordmark. Цветной оригинал допустим как существующий брендовый актив; глобальная навигация не должна брать у него мятный цвет. В мобильной строке знак не уменьшать до декоративной точки. Охранное поле не менее четверти высоты знака.

## Композиция

### Desktop ≥1280 px

Одна верхняя строка 56 px: бренд, название текущего раздела, справа одна основная кнопка. Навигация слева 200 px, фон белый, тонкая граница. Не повторять бренд в двух местах. Рабочая область без декоративного max-width, который оставляет полезную карту узкой.

На `/app/map`: toolbar до 56 px; ниже три области — реестр 272 px, карта `minmax(420px, 1fr)`, выбранный груз 288 px. Между областями тонкие разделители, не три больших карточки с внешними полями. Высота сцены по оставшейся высоте viewport, минимум 480 px. Map mode, zoom и fit — компактные группы поверх карты, не отдельные горизонтальные секции.

На 1024–1279 px: навигация сокращается до rail 72 px с доступными именами; выбранный груз показывается drawer поверх правого края только по действию, карта не сжимается до узкой полосы. На 768–1023 px: список 240 px и карта; детали drawer. Любой drawer должен закрываться Escape и возвращать фокус.

### Mobile 353–767 px

Шапка 56 px: меню, бренд, контекстное действие. Список шести разделов скрыт в меню. Следующая строка 44 px: «Карта» и выбранный груз / «Все перевозки». **Карта начинается не ниже y=100 px**, занимает `max(360px, 100dvh - 220px)` при закрытых панелях. Верхний toolbar имеет максимум две группы: 2D/3D и fit; zoom у нижнего правого края. Под картой свернутая панель перевозок 64 px: название выбранного груза, ETA, «Перевозки (N)».

Кнопка «Перевозки» раскрывает bottom sheet: поиск, строки, close. Выбор груза закрывает список и сохраняет карту видимой. Тап груза/маршрута открывает короткую карточку «Груз → состояние → действие»; «Подробнее» раскрывает паспорт. Не требовать жеста: любое перетаскивание панели дублируется кнопкой.

Если viewport слишком низок или открыт клавиатурный поиск, панель становится прокручиваемым диалогом. Тело страницы не получает горизонтальный scroll. На 200% zoom допускается адаптивное перестроение и вертикальная прокрутка; не уменьшать шрифты.

## Карта: информация и действия

Вид по умолчанию охватывает выбранный маршрут. 2D и 3D используют одинаковые выбранный груз, путь, узел и легенду. На mobile допустимо начинать с 2D ради читаемости; 3D доступен явно. Это не автосмена режима при каждом resize.

| Элемент | Что показывает | Действие и результат |
| --- | --- | --- |
| Строка перевозки | Имя; ID; откуда → куда; ETA; один главный статус | Выбирает груз, подсвечивает строку и путь, обновляет карточку; URL хранит shipment |
| Порт | Название; выделение при фокусе/hover | Открывает компактную карточку узла: имя, страна, роль в выбранном пути; релевантные грузы только по данным |
| Груз | Название и известный этап | Открывает груз; расчётную позицию не выдаёт за GPS |
| «Вписать маршрут» | Иконка fit + доступное имя | Умещает выбранный путь с учётом открытых панелей |
| «Весь коридор» | Отдельное действие | Сбрасывает только камеру, сохраняет выбранный груз |
| 2D / 3D | Видимое selected state | Переключает rendering, сохраняет контекст; WebGL failure ведёт на 2D |
| `+` / `−` | Масштаб | Масштабирует; не запускает autorotation |
| Источник | Короткая строка в углу | «Расчётная схема · обновлено …»; происхождение и ограничения по раскрытию |

Не размещать labels поверх друг друга. Названия портов выбранного маршрута приоритетнее всех остальных. При выборе route lines акцентируются, остальные уходят в muted. Legend компактна: «Принятый маршрут», «Альтернатива» только когда альтернатива реально открыта. Метрики вне canvas остаются HTML. Все порты должны иметь клавиатурный эквивалент — список узлов в карточке маршрута.

Карточка выбранного груза: имя и ID; маршрут; текущий этап; ETA и отклонение; одна причина внимания; главный CTA «Открыть перевозку» либо «Сравнить варианты» если пользователь уже открыл планирование. Не совмещать два primary CTA. Нет груза — спокойный overview коридора с «Добавить груз».

## Страницы и прогрессивное раскрытие

| URL | Первый экран | Основное действие | Раскрывается далее |
| --- | --- | --- | --- |
| `/app` | Заголовок «Обзор перевозок», компактные количества, пространственный обзор + короткая приоритетная очередь | Открыть первую проблемную перевозку | Все риски, события, аналитика; пустая очередь не занимает половину экрана |
| `/app/shipments` | Поиск, число результатов, быстрые статусы, читаемые строки | Открыть выбранную перевозку; глобально «Новый груз» | Расширенная сортировка/фильтры; состояние query сохраняется при возврате |
| `/app/map` | Реестр + рабочая карта + выбранный груз | Выбрать груз / открыть перевозку | Порт, детали груза, параметры карты |
| `/app/risks` | Очередь по серьёзности: проблема, груз, последствие, срок | Открыть груз или создать задачу | Форма задачи с предзаполненным грузом/проблемой; история выполненных отдельно |
| `/app/documents` | Груз, отсутствующий/проблемный документ, состояние комплекта | «Проверить комплект» | Файлы и требования внутри конкретного груза; статус «готово к проверке» не равен «проверено» |
| `/app/analytics` | Определение метрик и охват; сравнение маршрутов общей шкалой | Перейти к перевозкам выбранного маршрута, если фильтрация реализована | Методика и источники; не рисовать временной тренд без временных рядов |
| `/app/shipments/:id` | Уникальный заголовок груза, статус, ETA, текущий этап, карта и следующий шаг | Одно действие по фактическому состоянию | Документы, альтернативы, история, источники расчёта |

Паспорт: убрать дублирующий глобальный реестр перевозок и selector — человек уже внутри конкретного груза. Возврат «Все перевозки» над заголовком. Сводная строка ETA / этап / документы; вкладки «Обзор», «Маршрут», «Документы», «История». Default overview: карта слева, следующее действие справа. На mobile заголовок и сводка до 220 px, карта около 300 px, затем действие; sticky CTA снизу только если не дублирует постоянно видимый CTA.

Альтернативный план начинается кнопкой «Сравнить варианты». После открытия: текущий маршрут рядом с альтернативой, время/расходы/ограничения на одной шкале. Затем отдельная подтверждаемая команда принятия. После сохранения перечитать принятую версию. Три ссылки «ML-прогноз / Стыковки / Коридор» собрать в раскрытие «Расчёт и источники». Демо-сценарии — в дополнительном меню, не в главной строке реального груза.

## Поведение данных

Загрузка: skeleton соответствует конечной геометрии; header и map controls не прыгают. Нет данных: объяснить отсутствие и дать подходящий следующий шаг. Ошибка: сохранить введённые фильтры и последний доступный контекст, показать «Повторить». Пустой поиск: «Перевозок не найдено» + «Сбросить фильтры».

Данные с demo/scenario признаком явно отличать от действительных перевозок; не распространять демонстрационные показатели на производственную сводку без указания состава. Не добавлять live, online, фактическое движение, процент уверенности или экономию без соответствующего поля. Дата обновления — из успешного ответа/источника, а не бесконечно тикающие часы. Не подменять ошибку красивыми fixtures.

## Движение

Три осмысленные связи: (1) выбор строки сразу меняет выбранный путь и карточку; (2) открытие/закрытие drawer 200 ms с сохранением фокуса; (3) fit камеры 240 ms после явного нажатия. Reduced motion: drawer появляется сразу, камера меняет положение без перелёта; данные доступны без анимации. Постоянная анимация волны/пульса/порта не требуется. При скрытой вкладке и вне viewport рендеринг остановлен.

## Проверка готовой реализации

Статусы только PASS / FAIL / NOT_TESTED, рядом доказательство. Направление не подтверждает прохождение этих пунктов.

1. `/` визуально и функционально сохранён; Freight media, навигация и CTA работают.
2. Скриншоты 353×800, 390×844, 768×1024, 1024×768, 1440×900. На mobile карта начинается <=100 px; виден полезный участок маршрута и способ выбрать груз без прокрутки.
3. Ни один из семи разделов не имеет горизонтального overflow; контент 200% zoom читается.
4. На карте: выбрать другой груз → URL/строка/маршрут/карточка согласованы; нажать порт → верный узел; fit → весь путь виден; 2D↔3D → selection сохранён.
5. Browser Back и reload возвращают выбранный груз; закрытие mobile sheet возвращает фокус на кнопку. Меню не перекрывает активный sheet.
6. WebGL unavailable → рабочая 2D карта; API unavailable → реальная ошибка с повтором; никаких фиктивных успешных показателей.
7. Поиск + риск + сортировка дают согласованный список; сброс очищает критерии. Из карточки есть однозначный возврат к реестру.
8. Создать/изменить задачу, загрузить/проверить документ, принять план: видимый результат подтверждён повторным чтением. Ошибка сохранения не теряет ввод.
9. Контраст body >=4.5:1 и control/focus >=3:1 измерен. Проверен Tab, Enter, Escape, reduced motion; выбранные/ошибочные состояния читаются без цвета.
10. На карте измерен performance trace при выборе/zoom/fit; FPS не объявлять проверенным по screenshot. Видимый текст не превращается в мерцание при движении.
11. Отдельный независимый reviewer получает только актуальные screenshots/recording, размеры viewport, исходную задачу, границы бренда и обязательные ограничения. Не получает код, защиту решения, прошлые оценки. Для полной переработки — оценка 1–10 по oil-ui reviewer-manual; текущий документ не является этой оценкой.
