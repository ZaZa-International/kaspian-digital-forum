# ADR-0005: единый сценарный движок и явное ожидание парома

Дата: 2026-11-12 · Статус: принято · Цикл 3

## Контекст
Аудит нашёл рассинхрон: search игнорировал extra_customs_h, wind-only не менял
Monte Carlo, storm+wave давали разные результаты в point/MC, отрицательные
wave/wind давали отрицательную задержку. Ожидание парома (главная боль кейса —
стыковка ж/д↔паром) не моделировалось вовсе: base 122 ч против реальных 15–20
дней door-to-door.

## Варианты
1. Оставить как есть + подписи — нечестно и ломает демо-сценарий.
2. **Единый контракт сценария + явные компоненты времени** — один precedence
   (явная волна/ветер > шторм > live/fallback), ожидание = interval/2
   (допущение, MC ~ Uniform(0, interval)), пропуск рейса +48 ч при волне ≥ 2 м;
   ход/ожидание/задержка разделены в API и UI.

## Решение
Вариант 2. Все endpoint'ы (forecast/compare/search/exceptions/shipments/
timeline/ML/MC) принимают close/extra_customs_h/wave_m/wind_ms и применяют
их одинаково (тесты консистентности). Валидация диапазонов → 422. Время в
пути = ход + ожидание + задержки; граница системы: terminal-to-terminal,
door-to-door 15–20 дней включает оформление/последнюю милю вне модели.

## Последствия
+ UI и API дают один результат для одной конфигурации (проверено в браузере).
+ Стыковка ж/д↔паром объяснима и видна в каждом плече.
− Ожидание — допущение до появления реальных расписаний/снапшотов ASCO.
