## Что делать Курбану утром

1. **Принести файл кейсов** (PDF/DOCX/ссылка из чата организаторов)
   — скинуть в этот чат или запушить в репозиторий.
2. Как только текст кейса появится — сверить его с разделом
   «Как pivot'иться» ниже и переписать `data.py` под реальный кейс.
   Архитектура специально устроена так, что смена предметной области —
   это один файл данных + тексты на фронте, а не переписывание проекта.

## Как pivot'иться, если реальный кейс №2 — другой

| Если кейс про… | Что меняем | Сколько времени |
|---|---|---|
| Экомониторинг ООПТ | `STATIONS`/`PROTECTED_AREAS` → реальные территории, алерты → превышения ПДК | ~1 ч |
| Логистику «Север — Юг» | `PORTS` → маршруты и узлы, симулятор → время/стоимость маршрута | ~1,5 ч |
| Госуслуги / э-документы | Карта → реестр услуг, симулятор → калькулятор сроков | ~2 ч |
| ИИ / дипфейки | Добавить модуль проверки контента поверх того же API | ~2 ч |
| Маркетплейсы / e-commerce | Порты → склады и пункты выдачи, симулятор → спрос | ~1,5 ч |

Не меняется ничего из: `main.py` (эндпоинты), структуры фронта,
`run.sh`, Docker, тестового каркаса.
